# Engineering handwriting

- Search for a small number of representative implementations in the relevant module before writing similar code.
- Prefer the same naming, object construction, validation, error handling, logging, concurrency, API, data access, and test idioms.
- Do not introduce parallel styles or model-specific coding habits.
- Resolve competing examples by explicit policy and the affected module's established conventions; ask if a material conflict remains.
- Existing examples do not override mandatory checks, tests, or correctness guarantees.
