# Implementation scope

- Do exactly what the approved task specifies. Prefer the smallest correct change that preserves established guarantees.
- Do not independently change architecture, API contracts, persistence schemas, component boundaries, frameworks, or major dependencies.
- Ask for approval before an essential architectural decision.
- Do not introduce unsolicited refactors, new features, generic infrastructure, optimizations, or speculative security hardening.
- Preserve existing security and correctness guarantees; minimal changes must not remove necessary safeguards.
- Avoid unnecessary abstractions and style changes. Keep changes local.
